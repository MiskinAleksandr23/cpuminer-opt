# Сравнение двух оптимизаций SHA256d на одном ядре

Скрипт собирает **полный cpuminer**, проверяет правильность AVX-512 сканера и запускает майнер в штатном офлайн-режиме `--benchmark -a sha256d -t 1`. Пул, кошелёк и доступ к сети во время замеров не требуются.

## Запуск на Debian / Ubuntu

Нужен Linux x86-64 с GCC, Python 3.8+ и доступными внутри гостевой ОС флагами `avx512f avx512bw avx512dq avx512vl`, а также AES и AVX2. Перед сборкой скрипт проверяет модель CPU и набор инструкций, который GCC включает с `-march=native`.

```sh
sudo apt-get update
sudo apt-get install -y git python3 build-essential autoconf automake libssl-dev libcurl4-openssl-dev libjansson-dev libgmp-dev zlib1g-dev
git clone --depth 1 --single-branch -b perf/sha256d-combined-bench https://github.com/MiskinAleksandr23/cpuminer-opt.git
cd cpuminer-opt
python3 bench/sha256d/run.py
```

Если репозиторий уже склонирован, выполните в нём `git fetch origin perf/sha256d-combined-bench`, затем `git switch perf/sha256d-combined-bench`. Для копии, клонированной только с одной другой веткой, можно явно создать ссылку удалённой ветки командой `git fetch origin refs/heads/perf/sha256d-combined-bench:refs/remotes/origin/perf/sha256d-combined-bench` перед переключением.

**Обычный прогон занимает около 82 минут плюс сборка**. Сначала идут четыре разминки по 30 секунд, затем четыре серии. В каждой серии работают все четыре варианта по пять минут. В результате у каждого варианта будет 20 минут измерений. Процессы работают по очереди на одном и том же логическом CPU. Сборка по умолчанию использует одну задачу make. При работе по SSH оставьте сеанс открытым или запустите скрипт в tmux.

| Имя в отчёте | Порядок сложений T1 | Перестановка Ch/Maj |
|---|---|---|
| base | исходный | исходная |
| rounds | изменён | исходная |
| ternary | исходный | изменена |
| combined | изменён | изменена |

`base` использует исходные операции v26.1. Все варианты содержат одинаковое исправление полных хешей при редких совпадениях и один измеритель. `rounds` и `ternary` соответствуют оптимизациям из одноимённых экспериментальных веток. Бенчмарк измеряет штатный перебор nonce майнера. Прогнозы из предварительного стенда с 64 версиями заголовка к этому прогону напрямую не относятся.

## Только SHA-NI после предыдущего теста

После завершения текущего прогона на той же виртуалке обновите эту ветку и выполните:

```sh
git pull --ff-only
python3 bench/sha256d/run.py --sha-ni-only
```

Это отдельный режим для x86-64 с флагом Linux `sha_ni`. Он собирает только один новый cpuminer. Для SHA256d явно выбирается существующая реализация SHA-NI, которая обрабатывает два независимых заголовка за итерацию в одном потоке. Проверка подтверждает выбор сканера, наличие инструкции `SHA256RNDS2` в его функции сжатия и правильность хешей по OpenSSL. Для разбора машинных инструкций используется `objdump` из `binutils` (входит в обычную установку GCC на Debian/Ubuntu).

По умолчанию прогон занимает **20 минут 30 секунд плюс сборка**: разминка 30 секунд и четыре замера по пять минут. Действуют те же `--minutes`, `--rounds`, `--smoke`, `--cpu` и `--out`. Прежние измерения AVX-512 повторять не нужно. Текущий запуск пишет свой `summary.json` и `samples.csv` в новый каталог.

Скрипт читает последний завершённый AVX-512 отчёт из `bench-results/` с той же моделью CPU, номером логического ядра и длительностью окна. Если такого отчёта нет, выводится скорость SHA-NI самостоятельно. Если старые результаты лежат в другом месте, укажите `--compare-to /путь/к/старому/каталогу` (или путь к его `summary.json`). В новом отчёте `historical_comparison.sha_ni_delta_percent` показывает относительную разницу с прошлыми средними скоростями; положительное значение означает, что SHA-NI оказался быстрее. Это сравнение отдельных серий: нагрузка на VPS могла измениться между ними. Для этих процентов не рассчитывается парный доверительный интервал. Во время первого теста не запускайте второй на том же vCPU.

## Продолжительность и результат

```sh
# Быстро проверить сборку, корректность и запуск четырёх бинарников (40 секунд плюс сборка)
python3 bench/sha256d/run.py --smoke

# Увеличить каждое окно до 10 минут: 160 минут замеров плюс разминка и сборка
python3 bench/sha256d/run.py --minutes 10 --rounds 4
```

Каждый запуск создаёт новый каталог `bench-results/<время UTC>/`. Скрипт выводит точный путь. Чтобы задать каталог вручную, используйте `--out новый-каталог`. Для другого доступного логического CPU укажите `--cpu N`.

- **summary.json** — скорость в H/s, прирост относительно base и приблизительный 95%-й интервал по парным результатам серий. Основное сравнение — `combined` против `base`.
- **samples.csv** — порядок, число хешей, фактическая продолжительность, H/s и доля времени steal из Linux для каждого прогона. Сюда попадают и разминки с отдельной отметкой.
- **run.json**, журналы майнера и **build/build.json** — ядро CPU, порядок запусков, ревизия, компилятор, флаги и SHA-256 бинарников. Бинарник с обеими оптимизациями находится в **build/bin/combined**.

Скорость равна полному числу выполненных попыток, делённому на монотонное время работы потока, включая ожидание CPU. Время сборки, самопроверки и разминки исключено. В полных циклах из четырёх серий каждый вариант занимает каждую позицию один раз. Интервал основан на логарифмах отношений скоростей внутри каждой серии. Если нижняя граница интервала для combined выше +1%, серия даёт свидетельство прироста более 1% в этих условиях. На загруженной виртуальной машине интервал может оказаться шире самого эффекта. В режиме `--smoke` интервал не рассчитывается.

## Как устроена сборка

Скрипт архивирует локальный коммит HEAD в каталог результатов, выполняет autotools/configure и собирает проект. Для следующих вариантов он перекомпилирует объект SHA-256 с соответствующими переключателями и заново линкует cpuminer. Рабочая копия остаётся на той же ветке. При обычной сборке этой ветки включены обе оптимизации.

Перед замерами проверка линкуется с теми же объектами SHA, что и очередной бинарник. Она проверяет выбор 16-полосного сканера, найденные nonce, все 32 байта отправленных хешей и сравнение с порогом по независимому SHA256d из OpenSSL. Генезис-блок проверяется в каждой из 16 SIMD-позиций. При ошибке сборки, проверки или измерения скрипт прерывается и сохраняет уже записанные журналы.
